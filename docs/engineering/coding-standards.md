# Coding Standards

Follow the repository's existing framework and conventions.

## General

- Type safety where supported.
- Small focused components/functions.
- Centralized business/domain rules.
- No secrets in source.
- No hardcoded institutional facts scattered throughout UI components.
- Prefer structured content/data.
- Add dependencies only when justified.
- Keep static-hosting constraints in mind.

## Comments

Explain non-obvious WHY, not obvious syntax.

## Institutional data

Prefer central data modules or future API-backed content over repeated literals.
