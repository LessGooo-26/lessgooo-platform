# General Acceptance Criteria

All public features should:

- work on mobile;
- remain understandable with simple language;
- avoid unconfirmed institutional claims;
- avoid invented fees/schedules;
- use semantic HTML where applicable;
- support accessible interaction;
- avoid unnecessary large assets;
- respect static-hosting constraints;
- use centralized institutional data where practical.

Feature-specific acceptance criteria belong in the relevant product document or
implementation plan.
